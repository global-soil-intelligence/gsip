## Boundary and proposed files

Implement only deterministic synthetic source/draft/outbox/recipient behavior. One explicitly designated private simulator root owns aggregate counters and fake authority state for a simulation. Independent roots are independent simulations; there is no claim of a global quota or shared authority across them. A fake transport calls local methods and injects scripted delivery, reordering, disconnection, failure and lost replies. No HTTP client, socket/listener, URL, secret, contributor-directory scan, legacy-record importer, real enrollment or field export is introduced. Existing LIB-1/2/3, hosted/app/photo/public-reader code remains unchanged.

Proposed source files are `pipeline/node_exchange_simulator.py` (public synthetic API and state transitions), `pipeline/node_exchange_store.py` (private filesystem transaction primitive), `tests/test_node_exchange_simulator.py`, `tests/test_node_exchange_store.py`, and one short `docs/LIBRARY_EXCHANGE_SIMULATOR.md` example containing fictional fixtures only. These names are proposed, not created. No new dependency, CLI entry point, migration, worker dispatch or transport plug-in is required. Python standard-library filesystem/locking tools and the merged LIB-5A Python helper module are sufficient. Avoid turning a general transport protocol into a hook for real networking; only the explicit fake transport is supported.

## Exact proposed API and LIB-5A integration

`SyntheticExchangeSimulator.open(private_root, *, allowed_root, fixture_set, clock)` validates the designated root and opens/recoveries it under one per-root exclusive lock. `fixture_set` is an explicitly synthetic, in-process fake authority registry, not a locally imported record's verified/consent state. Durable simulated original-human/grant restrictions are monotonic; reopening with changed or missing fixture authority holds use rather than silently recreating permission. `clock` is a deterministic fake UTC clock; the simulator never sleeps or reads wall-clock credentials.

Public methods proposed for 5B:

- `enroll_scope(scope_fixture)` registers one exact normalized source/destination/scope and original fake human, immutable owner/origin facts, and its reserved refusal-fence capacity. This is local simulation, not real peer enrollment.
- `stage_declaration(scope, original_sample, original_measurement)` allocates recipient/scope aliases once, reads only the known synthetic fixture, checks current fake rights and capacity, and creates one immutable event/slot plus retained original byte buffer. Fixture UUID generation and serialization are explicit and deterministic; retries do not reserialize.
- `receive_event(original_bytes)` uses current fake authority and the existing alias map before any durable payload admission; envelope IDs, digest, parser success and cached receipts confer no authority.
- `withdraw_original(original_fake_human, original_sample_or_grant)` records original-source refusals and cleanup intent first, then erases covered source drafts/outbox/scientific payload. Later grants/IDs cannot revive it.
- `process_batch(fake_transport, *, limit=20)` processes eligible cleanup before declaration work using generation-bound claims and the fixed retry schedule. Claims are released before calling another endpoint; completion re-locks and conditionally checkpoints only an existing matching claim. It cannot write a removed event back into the queue.
- `create_synthetic_preparation(binding)` writes only a deterministic tiny synthetic fixture under the managed root, after a fresh fake-authority check, to exercise derived-file erasure. This supplies no training or field-preparation permission.
- `payload_status(binding)` returns generic `available_for_synthetic_simulation` or `held`, rechecking fake rights each time. Field training/evaluation/map/publication eligibility is always false.
- `counts()` returns engineering counts and generic outcome classes. Private receipts may bind opaque scope/event/alias identities; public logs/reports contain no payload, paths, grants, source hashes or holdout reasons.

LIB-5A author supplied these proposed interfaces: `prepare_node_exchange_event(bytes)` returns frozen normalized event, exact SHA-256 and immutable `original_bytes`; `parse_node_exchange_event(bytes)` is byte-only. Use the snake-case equivalents of `nodeExchangeStream`, `nodeExchangeSlot`, `checkNodeExchangeIdentity`, `bindNodeExchangeMeasurement`, `nodeExchangeRetirementAliases`, `nodeExchangeDeclarationCovered` and `advanceNodeExchangeHead`. The author confirms normalized 36-character UUIDs; root-container depth 1 and max 12; unsigned decimal integer lexemes; copying input before asynchronous hashing; value-based scientific equality; immutable slot/event conflicts; and monotonic synthetic binding. Retirement-alias extraction explicitly performs no authentication. Final exported names will be bound to the merged 5A head before implementation.

## Durable private layout and transaction protocol

Proposed root layout:

- `.lock`: mode 0600 regular single-link file; held with the existing exclusive local locking discipline.
- `state.json`: mode 0600 authoritative bounded metadata. Stores schema/generation, fake original identities and monotonic rights, enrolled scopes/fences, original-to-recipient alias relationships, immutable event/slot/digest ownership, separate source/receiver committed heads, claim/quota/capacity state, payload references and cleanup obligations. It contains no scientific tuple or secret. Minimal refusal entries are a distinct collection with only opaque approved identities and generic retired state; integrity digests never enter refusal entries.
- `source/events/<event_uuid>.json` and `recipient/events/<event_uuid>.json`: distinct mode 0600 exact original event bytes so source and recipient payload absence can be demonstrated separately. Their physical bytes both count. Covered declaration bytes are erased, while private slot/digest metadata remains separately identified.
- `drafts/<draft_uuid>.json` and `preparation/<artifact_uuid>.bin`: bounded synthetic-only managed files. All filenames come from validated UUIDs; no caller filename or external path is accepted.
- `staging/<transaction_uuid>-<object_uuid>.tmp`: bounded private same-filesystem temporary files. No old-state backups or unbounded history are accumulated.

Every directory is exactly private mode 0700; files exactly 0600, regular, single-link and size-bounded. Inspect ancestors before resolution. Use descriptor-relative, non-following directory and file operations, check inode/device/type/link/mode/size after opening, and recheck root identity before committing or unlinking. Do not rely on a resolved string or a pre-open symlink check as a race guarantee. Reject traversal, symlinked ancestors/root/lock/data/temp, special files, hardlinks and unknown managed-layout entries. Never follow, chmod, replace or erase an unsafe unexpected object. Shared/cloud/public roots remain prohibited by operator policy; path checks cannot prove absence of every synchronization provider.

One lock serializes all writers and readers that can confer simulated use. No lock is held during transport delivery. Each durable operation uses an authoritative generation and one pending transaction in `state.json`:

1. Validate fresh fake authority, immutable identity, layout and all logical/physical byte capacities under the lock. Persist and fsync a bounded reservation/intent before scientific blob writes. Rejected work writes no payload.
2. For withdrawal/retirement, the same first metadata commit activates all minimal refusals or the pre-reserved permanent scope fence and an erasure obligation before deleting payload. Such restrictions cannot be rolled back on failure.
3. Create/fsync bounded private blobs and publish with atomic same-filesystem operations, or erase only the exact validated covered managed files; fsync affected directories.
4. Commit finalized metadata atomically and fsync the root. New payload is visible only after finalization. Release byte capacity only after confirmed filesystem absence. A cleanup acknowledgment requires exact covered scope/aliases and a locked absence check, not a delivery receipt or a removed queue item.

On reopen, recover the pending transaction before admission, claims, inspection or use. Interrupted declaration creation removes only its validated new private blobs before releasing its reservation; an interrupted retirement preserves restrictions and remains pending until absence is verified. Corruption, unsafe files, fsync failure or unknown transaction state holds the root and returns a generic error. No crash recovery fabricates a predecessor, resets a stream, evicts a refusal or reopens a scope. This is local filesystem recovery, not database/network distributed atomicity; storage faults cannot be promised instantaneous erasure.

## Identity, rights, queue and fence semantics

A source alias is allocated once for an original synthetic sample/measurement and exact recipient/scope. Immutable original fake human/grant/sample/measurement facts precede recipient aliases. A measurement alias belongs to one sample within a stream, and its validated scientific tuple cannot change. New events repeating the same tuple do not create another independent sample, observation or contributor. Group only known original aliases of the same fake human. Digests never join another human or establish physical pairing. Missing origin mapping holds instead of guessing. Removing a working alias map never clears a durable restriction.

`synthetic_claim=true`, simulated sealed/withdrawn state and existing restrictions propagate across all known aliases of the same original sample; false/later grants/new UUIDs cannot clear them. All fixtures remain explicitly synthetic regardless of a simulated claim value. An incoming normal declaration for known sealed/withdrawn origins returns only a generic unavailable result. There is no hidden-label/holdout-membership disclosure.

Exact repeated event bytes are idempotent and preserve quota, attempts, slots and aliases. Changed bytes for an existing event ID, or another event/digest for an occupied slot, holds normal stream work. Use 5A normalized typed tuple equality for repeat measurement binding without a canonical-JSON claim. Receiver heads advance only over contiguous verified predecessors. Gaps hold payload and use; late covered declarations are validated in memory if needed for chain advancement and never written as science. Approved fake retirement applies its sample-wide refusal immediately even if gapped or a stream already has an identity conflict, while head/slot commitment remains strict. Extra measurement aliases require fake source ownership in that same sample; no claimed alias can poison an unrelated fake human.

Fake cleanup permission is distinct from ordinary fake transfer permission. Revoked ordinary rights never revive to send cleanup. Unknown/disconnected/unavailable/expired authority holds work without trusting a cached positive. No real cleanup credential mechanism is selected. Source withdrawal and declaration admission are serialized under canonical fake original-human authority before root state changes; all other canonical and recipient state live under the same simulator root lock. This demonstrates a fake local ordering, not a real hosted rights race.

Claims are bounded, private, generation-bound and recoverable. At most 20 events per batch; cleanup eligible first, independent of contribution quota; declaration work cannot starve cleanup. At most five transient attempts, with fake-time eligibility at 60/120/240/480 seconds; attempt five holds for operator attention. Disconnection/unknown rights and incompatible authority are non-consuming holds, distinct from a scripted transient transport failure. Terminal conflict stays held; no automatic ID replacement/reset. Lost declaration replies retry identical bytes; lost cleanup acknowledgments keep the obligation pending and allow an idempotent repeat plus fresh absence check.

Hard limits are aggregate for the simulator recipient, across all fake humans and streams: 100 enrolled scopes, 1,000 queued declaration events, 20 gapped events per stream, 10,000 retained sequence slots, 10,000 sample-plus-measurement refusal identities, 1,000 pending cleanup items, and 200,000,000 queued payload bytes. Enforce inclusive boundaries and reject one over. Reserve before claim/write; never charge an exact retry twice. Each scope has durable fence capacity reserved before any declaration admission. Cleanup coalesces by scope/sample. If a valid retirement cannot retain bounded alias, slot or cleanup records, commit that already enrolled scope's permanent fence first, hold all declarations/use there, and retain a generic pending-erasure obligation. Scope-wide erasure may reduce payload exposure, but it cannot fabricate the missing exact alias/slot acknowledgment. Unknown scopes cannot acquire mutation authority through a saturation path. No capacity is freed by evicting a tombstone, changing IDs or erasing a queue entry while its payload remains.

## Minimal clarifications before code

Root agreed the first clarification is needed and can be recorded in a separately reviewed `docs/spec-v10`; none changes 5A or chooses a real retention policy.

1. Preserve the existing 200,000,000 queued-byte cap and additionally apply the same cap to all retained managed declaration/draft/preparation bytes until actual absence is verified. Include distinct source/receiver copies. Claim/dequeue/success/false acknowledgment must not release physical-byte capacity. State a finite metadata bound and finite transaction staging bound; proposed initial values are 32,000,000 bytes for one metadata image plus at most one 2,000,000-byte blob staged per transaction (20-event batches consist of individual bounded transactions). At most two metadata images coexist during replacement. These are proposed additional local safety bounds requiring registration, not claimed approved values; test that the capped logical state fits or refuse earlier generically.
2. Specify that the scope's reserved fence and generic pending-erasure bit are part of its at-most-100 enrolled-scope record, separate from the 10,000 sample/measurement refusal identities and 1,000 cleanup items. A full alias/cleanup ledger must not require a fresh allocation to close a known scope. No normal dequeue or local operator method releases/reopens the fence.
3. Define daily admission charging and endpoint accounting. Recommend charge each distinct new declaration event at first durable source/outbox admission and independently at first durable recipient admission; both counters are per original fake human across scopes. Exact event retries are free; a new event repeating an identical measurement consumes a declaration unit. UTC day is sampled at first admission, persisted, and a retry after midnight is not a new event. Unknown-authority or capacity refusal does not charge; committed admission retains its charge after later withdrawal. This is two local enforcement views, not a combined count or global cross-root quota.
4. Confirm one simulator root is the aggregate boundary, with no global quota across independently created roots and no real source-adapter assertion. The same root lock owns fake canonical authority and recipient state; fake transport may demonstrate delayed/lost delivery but supplies no distributed atomicity claim.

These are the only implementation-blocking ambiguities identified in this planning pass. Other §16.13 choices remain real-sharing LIB-5C holds, not requests to choose credentials or legal purpose for 5B.

## Adversarial verification to write after authorization

- Strict 5A malformed/unknown authority fields and fake-source mismatch refuse before data read/write. Spy barriers fail any attempted HTTP/socket/listener/secret/environment credential access, external file read or contributor-directory scan. No tests or barriers were executed in this planning task.
- Crash at every reservation/blob/fsync/rename/erase/finalization boundary; reopen never exposes partial new work or resurrects covered science. Assert tombstone/fence durability precedes each unlink; capacity released only after validated absence; unsafe/corrupt recovery stays held.
- Symlinks at every ancestor/root/lock/state/source/recipient/draft/preparation/staging position; root replacement during a checkpoint; hardlinks, FIFO/socket/device/directory-as-file, wrong permissions, oversized metadata/blob, path traversal and unknown files. Verify no outside file is read, modified or removed. Use only disposable synthetic paths.
- Two processes/instances against one root race admissions near each cap, slot/event conflicts, same sample withdrawal versus queueing, and claim completion versus discard/retirement. Only matching generations checkpoint; no resurrection, quota duplication, incomplete fence or double alias allocation.
- Exact retry after restart and lost reply keeps identical bytes/digest/event/slot/aliases, including uppercase UUID spelling, whitespace and number-format counterexamples. Altered event or occupied slot holds. Same measurement different sample/context/protocol/science conflicts; identical repeated tuple does not inflate evidence; a later true synthetic claim monotonically restricts all known same-owner aliases.
- Retirement first, gapped retirement, retirement during conflicted stream, zero/100 alias lists, late covered declarations, wrong previous digest and irrecoverable gap. Sample-wide cleanup applies beyond the supplied measurement list. Unknown/wrong-owner aliases never add another human's restrictions. No head skips, reset, unsealing, new-scope escape, old-grant revival or cross-human digest join.
- Every logical cap at exact maximum and maximum+1, mixed humans/streams; fake human quota at 100/101 across scopes; exact retries and day rollover; queued versus retained physical bytes and duplicated copies. Saturation writes no partial payload, evicts no refusal and uses the already reserved scope fence at alias/cleanup/slot exhaustion.
- Priority cleanup after spent daily quota; 20/21 batch boundary; deterministic 60/120/240/480 backoff and five-attempt terminal hold; disconnection/expired/unknown authority consumes no failure attempts; lost/fake/wrong-scope/incomplete cleanup acknowledgments remain pending until fresh exact absence.
- Managed drafts, raw event bytes, normalized/derived science, working alias maps and preparation files disappear on covered cleanup; minimal refusal identities and separately identified private integrity metadata remain. Minimal tombstones contain none of payload/hash/context/reviewer/credential/location. Engineering reports/logs remain counts/generic; field/physical-pair/training/publication claims remain absent.

Acceptance requires an isolated implementation snapshot after 5A merge and clarified-spec merge, fail-before regressions for behavior, narrow filesystem/concurrency tests, unchanged existing library/hosted/phone suites, static checks, exact-hash independent review and green CI.
