# Private library exchange simulator

WP-LIB-5B implements only SPEC v10 §16.10–16.12's fictional local rehearsal. LIB-5A supplies strict event contracts and supplied-fact helpers. This package supplies a private filesystem ledger, an explicit fake authority, independent source and recipient admission views, and scripted in-process delivery. It introduces no CLI, credential lookup, network transport, peer enrollment, hosted integration, database migration, worker dispatch or dependency.

Every scientific value is generated by `SyntheticOrigin`; callers choose opaque fixture IDs, a bounded generator variant and fictional restriction flags. A received declaration must bind to a known generated origin and preserve its validated scientific tuple. This is not an importer for contributor observations, original files, photographs or laboratory measurements. Do not place real content or identities in the fixture/root. All results remain synthetic and unverified. `available_for_synthetic_simulation` permits only this local rehearsal; `field_eligible` and `verified_physical_pairs` stay zero. Model calibration, photo publication, capture, production, field preparation and public spectral release remain under their separate existing gates. LIB-5C remains held.

## Explicit local interfaces

`SyntheticExchangeSimulator.create(root, allowed_root, authority, clock)` creates one new designated root. `open(...)` opens its existing ledger without reinitializing missing, corrupt or ambiguous state. The caller provides an exact `FakeAuthority` and UTC `FakeClock`; there is no ambient clock, environment or external authority adapter. Changing the fixture identifier or the owner/peer tuple of an existing scope refuses the root. The fixture's active/current facts and the root's durable restrictions must both permit each admission/use.

Each declaration's immutable scoped measurement handle resolves back to the exact original fake human, sample, measurement and grant. A currently authorized sibling measurement cannot substitute for a missing or reassigned original. This exact check applies to recipient admission and retry, draft release, claim and stopped-claim recovery, conditional completion, payload use and preparation. Unknown original authority preserves the queue without spending a transient attempt. Sample-wide restrictions still propagate across known aliases; separately current cleanup permission can erase restricted copies even when their original measurement no longer appears in the fixture.

Before the first admission or draft, the simulator aggregates sealed and synthetic restrictions from every currently known original of that same fake human/sample. It uses the same aggregation to refresh existing groups across changed or missing grant labels; stored grant identity never changes, and known flags only become more restrictive. Within an active enrolled scope, restrictions persist before even a missing selected measurement can refuse the request. A known sealed sample creates no science payload, alias, slot, outbox or quota charge. A known synthetic sample's first and later generated declarations carry a true synthetic claim, including through restart and sibling omission. Existing accepted event bytes remain immutable; current canonical restrictions apply independently of their old claims.

Normal admission and use require one unambiguous current canonical grant matching the group's stored grant. Conflicting grants refuse generically before selecting a new grant or allocating science. If a known initial restriction cannot be represented by an unambiguous new grant row, the simulator conservatively activates existing scopes for that same fake human instead of forgetting the restriction; this permanent local fence needs the later LIB-5C protocol to resolve. Different humans sharing a sample identifier never contribute restrictions or grant conflicts to each other's group.

- `enroll_scope(scope_id)` reserves a known fixture scope and its permanent fence/pending-erasure fields before science is accepted.
- `stage_declaration(scope_id, original_sample_id, original_measurement_id, draft=False)` generates a new event from the original fixture. A distinct event repeating an unchanged measurement is a newly charged declaration. The returned receipt is private; its IDs/digest are not a public output.
- `queue_draft(event_id)` retains the accepted draft's event ID, aliases and exact bytes when releasing it to the queue. Draft bytes already consume the retained and queued budgets. Queuing/replay does not charge again.
- `receive_event(raw_bytes)` owns and prepares those exact bytes itself. There is no API accepting caller-supplied `Prepared`, SHA or a truncated set of prior facts as authority. The receiver checks current fixture authority, canonical restrictions, all prior event identities and scientific bindings; it admits a gapped declaration only into quarantine.
- `process_batch(FakeTransport(...), limit=1..20)` claims cleanup before declarations under the root lock, releases that lock during scripted local delivery, and checkpoints only an existing claim with its original nonce. The transport accepts a strict tuple of at most 20 `deliver`, `disconnect`, `transient` and `lose_reply` actions, followed by default local delivery. Its internal position stays bounded by the tuple. It has no URL, socket, callback or live adapter.
- `withdraw_original(human_id, sample_id)` and `withdraw_grant(human_id, grant_id)` affect only known fictional originals. Canonical grant/sample refusal precedes later admissions. Durable scoped refusals and cleanup intents—or the already reserved saturation fence/pending marker—precede deletion. Interrupted grant propagation resumes those intents before source science erasure.
- `set_scope_status(...)` changes explicit fictional current-state controls. `revoke=True` is irreversible in this ledger; setting other controls back to a current positive state cannot clear a canonical withdrawal or a saturation fence. Cleanup after normal revocation requires its separately current fake cleanup permission.
- `payload_status(event_id)` returns a generic held/available status; `create_synthetic_preparation(event_id)` creates only a registered fictional marker after a fresh check of admitted owned bytes. It starts no training or image/model work.
- `counts()` exposes aggregate counts and fixed synthetic/unverified labels. It exposes no IDs, digests, scientific values, reasons, hidden restriction labels, paths or credentials. Public errors are the fixed `synthetic exchange unavailable`, with no value-bearing exception cause/context.

These classes are developer rehearsal interfaces, not public agent tools or a real sharing service. Their fake facts cannot authenticate a contributor, establish a license, verify physical pairing or certify an instrument.

## One root and honest accounting

One root owns its fake canonical authority state, source/outbox view, recipient view, known origin aliases, restrictions and all managed bytes. Source and recipient copies share all limits; distinct role queue/slot records count separately. A second root is an independent simulation, not a global quota or shared authority system.

The metadata contains identity, restriction, ownership, queue, quota and integrity bookkeeping, not scientific/context tuples. Tuple equality is checked by reading bounded owned event bytes and applying the LIB-5A value comparison; this is not cross-language canonical JSON hashing. Known aliases group only the same original fictional human/sample. A forced UUID collision with another live alias or a minimal refusal is refused before source admission and charge; randomness does not authorize identity reuse. Equal source hashes or shared numerical sample IDs do not link different humans or increase independent counts. False synthetic claims cannot remove a known restriction; newly generated events propagate the group's permanent true restriction.

Each enrolled scope's fence/pending marker can activate without allocating another alias, slot or cleanup item. If a cleanup operation cannot keep its required bounded facts, it holds the affected known scopes before further normal admission/use and preserves the unresolved erasure obligation. Ordinary retries cannot reopen them. Provisioning a new scope for that same fake human is conservatively refused whenever any permanent fence exists, independently of the pending marker. Verified absence, a new grant or later label omission supplies no fence-release authority; this package has no fence-release operation. Unknown scopes gain no mutation authority. A directly received fictional retirement with no known durable source outbox also activates this conservative reserved obligation before deleting covered payload; it does not invent sender admission/head facts.

The same fallback covers both logical cardinality refusal and complete serialized metadata-image refusal during original withdrawal, recipient retirement, restarted withdrawal completion and cleanup-byte reservation. It retains the original withdrawal and activates only already reserved scope fields, without allocating an alias, slot, cleanup item or payload. It evicts no identity facts and remains fenced when capacity later becomes available. An unsafe filesystem or synchronization failure still returns a generic held error rather than claiming that restriction propagation or erasure completed.

If a known original has no durable origin row yet and that new row cannot fit, the fallback uses the unchanged snapshot and fences all already enrolled scopes for that same fake human; it does not allocate a new origin or affect another human. If no matching reserved scope exists, neither original nor grant withdrawal can claim a successful zero-count result without a durable restriction: it refuses generically, and the caller retains an unresolved withdrawal obligation. This local limit supplies no real retention or cleanup authority.

Initial sealed, synthetic and already-withdrawn restrictions are persisted before aliases, payload, quota or later admission checks can fail. A saturated new restriction row uses the same pre-reserved same-human fallback and generic unresolved-refusal rule. Thus a quota/capacity failure or later fixture omission cannot discard an already observed restriction. The fallback introduces no new alias, slot, cleanup item or payload and never consumes another human's reservation.

## Filesystem transaction boundary

The low-level `PrivateExchangeStore` owns the following exact inventory:

```text
<explicit private root>/
  .lock
  state.json
  state.next                 # at most one transaction replacement
  blobs/<opaque UUID>         # registered regular single-link payloads
  staging/<transaction UUID>  # at most one reserved payload transaction
```

The designated root and managed directories require mode 0700; files require mode 0600 and one link. Ancestors and each live root/lock/directory/leaf binding are checked without following links, including before returns. Payload sizes are checked with `fstat` before bounded reads. Enumeration is bounded by the permitted/registered inventory. Descriptor-relative operations retain inode/ancestor bindings; an existing store object cannot silently adopt a replacement root. `open_designated` explicitly binds a valid existing root anew.

One `flock` serializes all root metadata decisions. A session belongs to its creating process and actual thread object; foreign/inherited sessions cannot recover or mutate another live transaction, or release its lock. Files are published through an exclusive no-replace rename, never a transient hard link. Only validated registered regular single-link artifacts may be removed. Unknown files, orphan payloads, links, special objects, corrupt counters or changed roots hold the root; there is no recursive deletion, directory scanner or repair sweep.

A put reserves capacity durably before an empty stage is created. Its inode is recorded before bounded payload bytes are written and synchronized. Recovery removes only that transaction's validated registered stage/final inode, then rolls back unaccepted admission metadata. An empty stage whose inode was not yet recorded is ambiguous and remains held. A partial/corrupt replacement image likewise remains untouched and held. Erasure records restrictions and exact registered targets first, then unlinks validated files, synchronizes directories and releases capacity only after absence. A failed erase resumes the same restricted transaction. Filesystem synchronization failures can leave a durable restriction and unresolved payload; a generic error is not a completion acknowledgment.

## Delivery, retry and acknowledgment boundary

Recipient heads derive exclusively from recipient-admitted slot facts; source facts never manufacture receipt of missing declarations. Identity/byte/scientific conflicts hold the stream. Current authenticated fake retirement is processed before gaps or slot conflict so an older declaration cannot revive a refused alias. Retirement is sample-wide even when its measurement list is empty. Known same-human aliases inherit the refusal and cover source/recipient declaration bytes, drafts and every registered preparation; working alias/binding mappings are removed after erasure, while minimal refusals and private sequence/digest metadata survive.

Every open and operation checks the complete role/stream/measurement binding-key set against retained declaration event/blob facts. Each binding must reference a declaration in its actual admitted stream with the same role, lineage, sample and measurement. Missing or redirected index entries hold the root generically before admission or use; the simulator does not silently repair contradictory metadata or treat omitted prior facts as authority. Identical repeated measurements share one binding per role and stream. Drafts and gapped recipient declarations remain covered; erased payload roles require no scientific binding, while their minimal slot/digest facts remain. This validates controlled corruption of fictional metadata, not a claim of authenticated storage, rollback detection or an ordinary API route that produces such corruption.

Every delivered retirement passes the same exact identity and recipient-slot checks, including after another scope's cleanup has erased the working aliases. Retained original/event and refusal facts bind that erased alias to its known scope/sample; all listed measurement handles still need durable refusal coverage. Valid recipient retirement slots persist without scientific payload or a fabricated source role, so later unrelated samples can follow the delivered retirement predecessor normally. Exact-byte cleanup retries remain bound to the original event/digest after all cleanup bytes are deleted; changed-byte/event/slot retries cannot acknowledge absence.

A genuinely missing predecessor leaves the retirement slot gapped without inventing a recipient head. Consecutively validated later arrivals can advance only through their exact predecessors. A known contradictory predecessor or successor is checked on a candidate: its proposed role/event/slot/head changes are discarded, the scope is held for conflict, and canonical refusals and rights erasure remain effective. A refused late scientific declaration does not become an admitted predecessor merely because source facts exist; any remaining gap stays held. Current separate cleanup permission and logical/metadata capacity reservation still precede receipt or absence acknowledgment. A refusal activates the existing affected scope fences and preserves the exact unresolved cleanup intent.

Cleanup is prioritized independently of the daily scientific admission quota. Only explicitly scripted transient failures spend attempts: five total, with delays of 60/120/240/480 seconds, then held. Disconnected, unknown, expired and otherwise unavailable outcomes preserve the intent without spending a transient attempt. A stopped claim has a separate local 600-second recovery rule: after fresh authority becomes available, it consumes a transient attempt and waits the corresponding delay before a new nonce can retry the original bytes. This is not the imported-photo 300-second lease. A delayed old nonce never removes/recreates a newer or erased queue record.

A matching receipt is not sufficient to finish a declaration: the simulator also checks the receiver's own admitted identity and exact registered bytes. Cleanup completion requires exact stream/scope/sample/list/event/digest agreement, current fake cleanup permission, durable refusal coverage and absence of **all** known covered science copies throughout the root. The entire managed inventory must remain safe. A false acknowledgment, cached status, lost reply, newly present orphan or delayed completion cannot make a held root available. Successful cleanup removes only its pending intent/retirement bytes; accepted daily charges and minimal refusals remain.

## Evidence and limits

The tests exercise generated camera and instrument records, replay/restart/midnight, role-head separation, immutable tuples, same-owner lineage, current authority, false receipts, delayed delivery versus withdrawal, interruption recovery, daily and cardinality bounds, saturation fences and process contention. Store tests cover actual byte boundaries, no-follow/inode/link/permission races, process crashes and process/thread session affinity. Some large logical cardinality checks use exact limit projections plus smaller end-to-end contention cases; these are engineering bounds, not capacity/throughput measurements. The delivery receipt records actual counts/checks and fail-before guard/order mutation evidence after the exact candidate freezes.

The ledger is not a signed authority, source authentication protocol, backup/rollback detector, secure erase proof or distributed transaction. A fresh independent root cannot prove global quotas or prior restrictions. It claims no immediate erasure of unreachable/unmanaged copies, released datasets or models. Private exact-event digests/original lineage retention remain unresolved for real data under LIB-5C. No real contributor acceptance, credential, retention policy, QA/holdout authority, calibration approval, field training, public map/model release, useful adoption or deployment readiness is supplied by this rehearsal.
