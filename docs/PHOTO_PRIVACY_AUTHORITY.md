# Private photo privacy authority (WP-6fA)

This additive package implements [SPEC §15.5–15.9](SPEC.md#155-wp-6f-private-state-policy-and-authority-v8-architecture-proposal). It creates private state and nine service-only RPCs. It selects no detector or calibration, provisions no reviewer, starts no remote worker and leaves photo publication closed. Existing QA, settlement, public photo fields, client RPC grants and contributor-rights worker signatures/bodies remain unchanged. WP-6fB supplies private screening/review tools; WP-6fC enforces exact-byte export.

Every legacy and new A/B/C photo begins at revision zero, pending, with an unknown sanitized digest. The migration reads existing database relationships without downloading Storage objects. A historic withdrawn grant is cleaned immediately, preserving opaque refusal identities. Previously passing QA confers no privacy clearance.

## Authority and state

The eight `private.photo_privacy_*` tables are policies, state, content, jobs, screens, operators, reviews and tombstones. All enable restrictive RLS denying client rows and deny direct table privileges to `anon`, `authenticated` and `service_role`. No new private-schema naming privilege is granted. Each public dispatch uses a SQL-standard, dependency-bound invoker body with an empty search path; only `service_role` can execute it. Private privileged bodies also pin an empty search path. Helpers are not independently callable by API roles.

Only owner-admin database administration can select an immutable policy, attach its owner approval receipt, mark deployment ready, open the independent publication gate, or provision/revoke personal operators. No worker/export/review RPC grants that authority. No operator is created by this migration. Owner provisioning and production activation remain separate deployment decisions.

A policy pins screening/calibration versions, detector/calibration manifest hashes, the card-margin version and bounded configuration. Its only allowed update attaches one owner approval SHA-256 to a previously unapproved immutable policy. Selecting a policy or changing deployment/publication state advances the server policy revision; old screens/manual clearances become ineffective. Gate opening requires a selected owner-approved policy and deployment readiness. The migration initializes all of these unset/false.

A personal operator token is exactly 64 lowercase hexadecimal characters representing 32 random bytes. The private mapping stores SHA-256 of its UTF-8 text, an opaque operator UUID, a live `auth.users` identity and an active flag. Private review receives the token only in the authenticated request body. Provisioning uses owner administration/secret stores after a separate go; no service-accessible provisioning or allowlist CRUD exists. Tokens never belong in CLI arguments, logs, CI output, errors or agent surfaces. The audit derives the operator UUID from this live mapping, never caller identity/name.

A human `privacy_risk` withhold is permanent for the photo UUID. A new object/path, content revision, policy generation, automatic completion or later human clear cannot reverse it. Source/rights erasure removes private payload while retaining minimal opaque refusal records. Those records contain identity kind/UUID, original opaque grant UUID and refusal reason; no image digest, path, detector evidence, auth identity, token, reviewer identity or account context survives there. Retired screen/review UUIDs cannot name new payload after erasure. A withdrawn/deleted photo UUID cannot be rebound, even with a new path/owner.

## RPC contract

All RPCs require an actual `service_role` claim as well as function permission. New photo admission and all nine private RPCs require PostgreSQL `READ COMMITTED` (the checked local/default transaction isolation) so rights queries refresh after contributor-lock waits. They fail closed with generic `55000` under repeatable-read or serializable snapshots; they never change connection isolation or live gates. UUID text uses the canonical 8-4-4-4-12 hexadecimal shape, accepts any version/variant bits and normalizes case. Digests are lowercase 64-hex; version strings are 1–64 ASCII letters/digits/dot/underscore/hyphen. Revisions are nonnegative integers and caller envelopes reject extra/missing keys, booleans-as-integers and fractions. JSONB is already decoded by PostgREST: SQL cannot detect duplicate raw JSON keys or original transport whitespace. Its size checks apply to normalized UTF-8 JSONB text; raw parsers/transport bounds remain the caller's responsibility.

Supported passes clear; flags require review; error/unsupported remains error. Exact completed retries are allowed only while content/policy/rights remain current and no permanent withhold exists. |
| `fail_photo_privacy_job(p_lease_id,p_error_code)`           | Persist only one finite generic error code and bounded retry state.                                                                                                                                                                                                                               |

Unknown byte/policy state returns null.                                                                                                                                                                         |

Withholding is permanent.                                                                                                                              |
| `authorize_photo_privacy_export(p_request)`                 | Strict unique ordered batch, up to 10,000 entries/8,000,000 normalized UTF-8 bytes; return policy capabilities plus per-photo booleans in input order. Recheck current gate, bytes, screen/manual disposition, rights, finalized QA, licensing, approved attribution and nonsynthetic provenance. |

Worker leases last 300 seconds with five attempts per content/policy generation. Storage/detector/timeout failures and expired attempts back off 60/120/240/480 seconds before the next attempt; attempt five is terminal. Decode/sanitize/unsupported failures are terminal immediately. New actual content or policy generation creates a fresh budget. Stale or expired leases cannot update current state.

Screen receipts are bounded to 16,384 normalized UTF-8 bytes and have the exact SPEC shape. They store finite result/candidate counts, policy manifests and optional narrow card-exclusion evidence. Used evidence pins image dimensions (at most 40 million pixels), the actual row-major uint8 mask SHA-256 (0 included/1 excluded), strictly between zero and all pixels excluded, and the selected margin version. Unused evidence is null. No OCR, face/text boxes, crops, coordinates or arbitrary errors are accepted. SQL checks declaration shape/binding; detector geometry/actual mask correctness are WP-6fB responsibilities. Faces always cover the complete frame. Card exclusion applies only to scene text and never supplies a soil mask or face exception.

| -------- | -------------------------------------------------------------------------------------------------- |
| `22023`  | Invalid/oversized strict request, finite enum or type.                                             |
| `42501`  | Service, live source/auth or personal-operator authorization refused.                              |
| `WD001`  | Rights withdrawal/covered request or opaque retired source identity.                               |

Errors from new authority functions are generic and do not echo tokens, paths, detector evidence or incoming payloads. Existing rights errors retain their existing contract.

## Rights, locking and exact-byte export

Normal private operations lock contributor, then explicitly lock the submission parent before its photo, followed by live auth, private content/job and policy state. Both source row locks use `FOR SHARE NOWAIT`: a busy source returns generic `PP002` rather than creating a wait cycle against parent deletion, photo deletion with its existing provenance-parent refresh, or a bulk deletion in another parent order. Claim skips busy candidates and export returns false for each busy source; surrounding exception subtransactions release skipped contributor/source locks before scanning another candidate. Human review locks live operator auth before its operator mapping, matching auth deletion's cascade order. Export batches acquire contributors in UUID order before sources/private rows. A selected policy/gate update seeks no contributor/source locks. Direct source DELETE/UPDATE already owns its source row and takes no contributor lock in its additive cleanup/invalidation hook; this avoids a source/contributor inversion. Tests exercise both directions and pause inside partial source/rights lock boundaries on separate real connections, including optional C insertion for both withdrawal kinds.

An early `BEFORE INSERT` photo admission trigger takes the contributor lock before source constraints/FK/private-row locks, refreshes the original parent/grant relationship and rechecks committed withdrawal/covered-request state after waiting. Its parent row lock also uses `FOR SHARE NOWAIT`. It retains the existing public withdrawn-photo error message and leaves all public RLS and column privileges intact. This prevents an authenticated optional C insert whose statement began before withdrawal from recreating private payload after that withdrawal commits. The `AFTER INSERT` initializer runs while those contributor/parent locks remain held. Existing library rights hooks supply the canonical contributor-first withdrawal/request lock. Additive grant/account hooks retire opaque IDs and erase content/jobs/screens/reviews atomically. Source deletion performs the same erasure before cascade. A completion guard refuses the unchanged old `complete_deletion_request` while any covered private payload remains, including privileged fault-injected orphan jobs, receipts and audits. Empty older requests cannot bypass the guard. Existing old `apply_deletion_request` cleans the new payload through source/rights hooks without a signature/body replacement.

The trusted worker registers the actual promoted sanitized JPEG buffer. Export must preserve that exact canonical buffer and assert its metadata is already clean; re-encoding or another sanitize pass changes the representation and requires a fresh screen. Immediately before final artifact promotion, WP-6fC recomputes SHA-256 on staged bytes and calls fresh authorization with that binding. Pending/review/error/withheld, stale versions or a closed/missing authority yield structured data only, with no photo reads, URLs, image shards or training bytes. Reused output directories must obey the current gate. The database receipt authorizes the current transaction; it cannot promise filesystem/Hub atomicity against a later withdrawal, so existing takedown/purge obligations remain.

## Local completion evidence

The package adds strict pgTAP/role/privacy/rights regressions, a prior-schema fixture and migration assertions, and `scripts/test-photo-privacy-concurrency.py`. `scripts/db-migration-test.sh` keeps the existing library concurrency hook and runs the separate photo hook afterward in its throwaway cluster. The race runner accepts only an explicitly disposable `gsip_lib4b_*` local database/socket/port; it discards earlier synthetic source fixtures after migration assertions, creates EMPTY geometry only, suppresses tokens/private request payloads and reports booleans/counts. No production credential or Storage download is required.

Passing local tests establishes code behavior on synthetic fixtures. It does not establish detector licensing, calibration quality, owner operator provisioning, production deployment or photo publication approval.
